# 01 业务挖掘

> 合成训练成果。任务状态区分已完成的资料/代码与仍待实际用户或生产授权的验证。

从经营目标、真实事件和指标基线中判断是否值得立项。

## 识别业务机会

任务编号：`opportunity-trigger`。状态：已完成。责任角色：顾明岚 / 林亦舟。

交付：业务机会清单。

触发事件是客户取消证书偏好后，旧筛选表仍将它当作硬条件（fsg-recruiting-f11）。业务问题不是缺少生成式摘要，而是条件分类、版本和交接来源失配。维持现状会重复核对并传播过期要求，优先验证一页缺项清单的价值。范围限制为招聘需求简报与面试安排；不进行候选人排名、筛除或录用。

证据位置：docs/01-opportunity.md；docs/evidence/interviews.json；证据：f10,f11,f15,f00,f05。

## 建立现状基线

任务编号：`opportunity-baseline`。状态：已完成。责任角色：林亦舟 / 叶书。

交付：指标基线与价值假设。

基线为实验室合成样本：40份岗位简报、120条面试安排、返工核对9小时（fsg-recruiting-f12），不能推断为企业月度真实数据。粗算每份简报分摊13.5分钟，仅用于情景分析。正式测量应逐单记录发生时间、接收时间、首次处理和返工处理分钟数；以完整观察窗内全部简报为分母，缺失值单列，林亦舟采集、叶书复核。

证据位置：docs/01-opportunity.md；docs/evidence/interviews.json；证据：f12,f13,f51,f53。

## 确认立项与决策链

任务编号：`opportunity-mandate`。状态：已完成。责任角色：顾明岚 / 傅景 / 叶书。

交付：项目章程与利益相关者地图。

顾明岚决定试点范围；傅景代表审核质量视角，保留停止权；叶书确认结果用途。一线由林亦舟参与，唐映秋负责交接，秦芮负责系统边界。预算约束是四周、两名业务骨干每人每周不超过4小时，不等于已经批准现金预算。真实数据授权、费用审批人和正式签署版Brief仍须补证。

证据位置：docs/01-opportunity.md；docs/evidence/interviews.json；证据：f03,f04,f40,f41。

## 关卡结论

业务负责人确认问题、指标口径与调查范围。

本阶段文档与演练证据可审查；真实业务批准、真实UAT及正式签收均不得以自检代替。
