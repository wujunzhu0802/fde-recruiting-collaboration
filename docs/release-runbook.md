# 发布、回滚与交接手册

版本1.0.0，仅本机合成演练。正式上线NO-GO：SSO、租户隔离、真实只读接口、正式数据授权、完整读取审计、真实UAT、预算和具名签收均未闭环。

## 安装与运行

Python 3.10及以上，不依赖第三方包即可运行原型。仓库根目录执行 `python -m src.server`，打开 http://127.0.0.1:8000 。Ctrl+C停止。端口冲突可用 `python -m src.server --port 8010`。数据位于runtime/demo.sqlite，已在gitignore中排除。复现测试：`python scripts/verify.py`。

## 本机发布与恢复

1. 固定Git提交及verification.json中的源码哈希，完成全部回归。
2. 停止演练服务器后，将runtime/demo.sqlite复制为已知可用备份；没有数据库时保留空环境。
3. 启动新版本，使用normal.json创建→质量确认→检查审计。
4. 发现401/403异常、旧版被确认、重复单或接口错误，停止服务器，记录版本及影响范围。
5. 恢复已知源码版本与数据库备份，重新启动，再走一单正常与旧版异常样本。
6. 原始失败单不得假装已恢复；在事件记录中保留问题、备份和恢复确认。

实际执行证据在verification.json：备份一个已确认单→增加故障单→恢复→验证原单与数量。本次没有执行生产发布，不用本机结果声称达到生产RTO/RPO。

## 交接资产与责任

交付README、九阶段报告、原始访谈、台账、需求追溯、契约、源码、样本、测试及流程图。建议秦芮接技术、唐映秋接流程，林亦舟使用，傅景质量，叶书确认用途，顾明岚决定继续。真实支持渠道、SLA、值守和签收人须另行指定；本仓库没有伪造签名。

操作复述题及真实在线角色回答在virtual-reviews.json。接手人需自己演示一次旧版退回、一次超时转人工、一次备份恢复后才能真实签收。
