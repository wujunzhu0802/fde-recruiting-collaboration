# 现场调研分析

## 调研范围与证据性质

在同一个fsg-recruiting合成场景中，对业务、一线、交接、技术、质量和客户六个视角开展36轮基础访谈，采集36条事实；另完成9次验收、评审、交接与事件问题。没有进入上海外服真实工作现场，也未取得真实人员、简历或业务日志。

## 角色与分工

- 顾明岚：服务业务负责人，确定目标、试点范围与投入限制。
- 林亦舟：招聘与用工服务顾问，还原条件分类和资料核对问题。
- 唐映秋：排期与培训协调员，跟踪版本、未结项、交接接收人与截止时间。
- 秦芮：数据与系统工程师，核实字段、只读导出、更新时点与故障路径。
- 傅景：质量复核负责人，核对授权用途、来源、人工确认和停止条件。
- 叶书：客户岗位负责人，核对业务口径、对外用途与反馈恢复需求。

## 现状链路与判断

客户访谈→需求条件确认→材料整理→面试排期→反馈归档（f01、f20）。[现状流程图](flowcharts.md)进一步显式标出6个判断：信息与分类是否明确、客户是否确认、需求是否变更、排期是否冲突、反馈是否完整且版本正确、复核是否通过。不满足条件时回到澄清、协调或反馈补全。

## 主要发现及影响

1. **条件分类和版本失配。** 证书偏好被旧表当作硬条件，导致错误要求传播（f11）。优先保留原文与版本，未经人工确认不能继续交接。
2. **实际发生与系统回填不同步。** 群消息先处理、后填表（f13）。不能把回填时间当作业务等待或处理时长，也不能用两张汇总表直接比较改善。
3. **交接信息不足。** “已处理”未说明最新版本、责任人、未确认事项及截止时间（f23、f25）。应以明确的交接清单替代口头结论。
4. **来源与访问边界未闭环。** 系统缺统一关联编号，只允许脱敏只读导出（f30–f32）。当前原型使用自建合成样本，不能宣称真实集成已通。

## 分歧与交叉核对

业务部门强调尽快安排，顾问要求先明确可验证条件（f50），两者并非可以互相替代的目标。方案以“先确认、后交接”为默认路径，紧急例外需具名负责人决定；不能把客户急迫自动解释成授权。

## 四来源收敛

- Buyer：目标与范围已有角色陈述；真实预算批准仍缺。
- Operator：具体模拟事件、现场习惯与缺项清单诉求已采集；原始业务日志仍缺。
- Brief：已单独导出 [平台原有四份训练资料](original-materials/README.md)；它们不是正式客户签署文件，也不是已收到的真实附件。
- Industry：官网支持业务背景，不能证明内部数据权限或本场景的经营指标。
