# 业务挖掘

项目：招聘需求澄清与面试协同。调研对象为FDE实验室六个虚拟角色；下述案例与指标均是合成训练材料。

## 触发事件与业务机会

客户已取消某项证书偏好，筛选表仍把它作为硬条件（fsg-recruiting-f11）。一线反复核对岗位条件，面试反馈又未关联当时的需求版本（f10）。值得优先验证的机会是让“必备/偏好分类、版本、来源、人工确认”随单据一起交接，而不是增加一份泛化摘要。林亦舟明确需要一页缺项清单及来源位置（f15）。

## 目标与范围

业务目标是减少招聘需求简报重复核对，同时保持人工责任和来源可追溯（f00）。先验证单批次、结构化资料核对；不自动评价、筛除或录用真实候选人，不发送外部通知，不写回生产系统（f05、f32、f52）。现状流程图不引入AI。

## 现状基线及测量计划

实验室给出模拟40份岗位简报、120条面试安排、返工核对9小时（f12）。这些不是企业真实业务统计，也没有可核对的逐单原始时间日志。后续需逐单采集首次处理分钟数、返工分钟数、等待时长、确认完整率，区分业务发生时间与回填时间（f13、f34），由林亦舟记录、叶书复核。

## 立项与决策链

顾明岚负责业务范围，傅景保留质量叫停权，叶书确认用途。四周试点、两名业务骨干每人每周不超过4小时是合成投入限制，不代表已批准现金预算（f03、f04）。真实客户Brief、资料权限和审批签字仍需补证。

## 机会判断

先改进人工模板，再用确定性规则核对字段、版本和排期。现有证据支持离线训练原型；尚不支持真实生产扩围或宣称已经节省成本。报价与ROI均为情景假设，详见 [ROI](roi.md)。
