# 受控试点与UAT执行单

状态：本地工程验证已执行；虚拟角色确认提问已执行；真实用户独立操作与30份业务需求UAT未执行。

## 试点计划

四周单一批次；业务负责人顾明岚、使用者林亦舟与唐映秋、质量傅景、技术秦芮、客户叶书均为合成场景映射。两名业务骨干总计最多32小时。正式项目需另外取得真实参与者授权。

目标集30份需求，须全部区分硬条件/偏好、反馈关联当时版本、来源可定位并有人确认。对照为不使用工具的标准人工模板，按复杂度配对或交叉分组，使用同一观察窗，分开记录处理与等待。以下每项至少包括正常、异常和退回再提交。

## 操作脚本

1. 招聘顾问打开正常样本并生成核对单，记录能否独立完成、耗时、错误数与帮助次数。
2. 切质量角色，核对来源，确认并查看审计。观察用户能否区分“待人工确认”和“已确认”。
3. 切异常样本，发现待澄清证书偏好、旧版反馈及重叠排期。用户须退回，不能点击通过后继续。
4. 修正后用新请求键生成新单，引用新版资料；旧单保留。
5. 用顾问尝试确认，预期403；用旧revision确认，预期409；同键重复提交只能有一单。
6. adapter_mode设为timeout，用户应知道找秦芮与唐映秋并保留来源，不声称已读取最新结果。

每项记录：用户代号、样本、版本、开始结束时间、处理/等待/返工分钟数、是否独立完成、障碍、缺陷编号、验收意见。实际记录没有采集前不得填造数字。

## 退出与继续

出现越权确认、旧版自动通过、真实资料误入或错误影响候选人即暂停；业务或质量可叫停。完成率、时间节省、误报阈值需真实业务确认；目前不批准生产扩围。虚拟角色回覆只能证明已询问条件，不证明他们运行了本地原型。
